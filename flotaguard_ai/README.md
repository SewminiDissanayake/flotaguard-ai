# FlotaGuard AI

**One-hour-ahead flotation quality early-warning prototype** for mineral processing.

FlotaGuard AI uses current-hour flotation process summaries plus the latest six hourly silica quality results to:

- forecast **next-hour % Silica Concentrate** with XGBoost regression;
- estimate the probability that next-hour silica exceeds the prototype quality threshold with a separate XGBoost classifier;
- identify the current **process pattern** with K-Means clustering;
- surface out-of-training-range inputs instead of silently producing a trusted-looking result.

## Why this version is different from the exploratory notebook

The original notebook used a random row split on highly time-correlated plant data. That produced an optimistic regression result around R² 0.91, but it is not an appropriate claim for future operation. This competition version fixes that by:

1. aggregating process rows to **hour-level summaries**;
2. changing the task to a useful **one-hour-ahead forecast**;
3. using a strict **chronological 80/20 holdout**;
4. removing target leakage and mock/random fallback predictions;
5. validating alert performance on a genuinely later test period;
6. using exact feature names and rejecting missing/non-numeric inputs;
7. labeling K-Means states from their observed training silica profiles instead of inventing absolute “critical/optimal” meanings.

## Validated prototype performance

The included `models/metrics.json` is generated by `train_models.py`.

- Regression R²: **0.5904**
- Regression MAE: **0.5444 percentage points**
- Alert precision: **0.7417**
- Alert recall: **0.7417**
- Alert F1: **0.7417**
- Test period: strict future chronological holdout, **819 hourly windows**

These are prototype results on the supplied historical dataset. They are not a production guarantee.

Place the original CSV one directory above this folder with the filename used in `train_models.py`, then run:

```bash
python train_models.py
```

## Important positioning for a competition pitch

Say: **“FlotaGuard AI is a human-in-the-loop decision-support prototype that forecasts next-hour silica quality risk.”**

Do not say: **“It controls the plant automatically,” “it is 91% accurate,” or “3.5% is a universal industry standard.”**

The 3.5% silica threshold is a **configurable prototype threshold** used to demonstrate the alert workflow. A real plant would set and validate its own quality specification.

## Production roadmap

A production deployment would need live historian/SCADA integration, plant-specific retraining, drift monitoring, calibrated alert thresholds, cybersecurity controls, audit logging, operator acceptance testing, and fail-safe operational procedures.
